## Detail: Refresh mid-fill (CHR3-001 / 002 / 007)

Intended (docs / CHR2-003): Refresh keeps UI + OpenClaw CDP + fill CfT on CAPTCHA/Ready.

Actual:

1. `_kill_all_tracked_child_procs()` — **always** (kills `fast_fill` / tailor / agent).
2. `_kill_jh_associated_browsers(preserve_fill_cft=…)` — first pass may preserve.
3. Server exits → **`finally` kills CfT again without preserve** (and still skips only `openclaw browser stop`, not the CfT process itself).

So Refresh mid-hold is unsafe; docs overclaim.

## Unnecessary / confusing tooling

| Item | Why confusing |
|------|----------------|
| **`./open_partyrock.sh` vs `openclaw browser open/start`** | Shell is the safe CfT+pin wrapper; raw OpenClaw can still prefer `Google Chrome.app` until pinned. Two “open PartyRock” stories. |
| **Legacy `partyrock_chrome_profile/`** | Still torn down everywhere; opener retired. Comments still tie it to `open_partyrock` (CHR2-008). Dead path noise. |
| **`scripts/chrome_for_testing.py` + `open_partyrock.sh` + server `_ensure_openclaw_*`** | Three ensure paths; behavior mostly shared but failure modes differ (CLI exit vs warn). |
| **`run_dashboard_supervised.sh` vs Desktop/`launch_dashboard.sh`** | Supervised skips UI window lifecycle; PLAYBOOK still nudges bare `server.py`. |
| **Manager `chrome_count` + BROWSER_CAP `pgrep`** | Meaningless / over-count; honor-system cap (CHR2-006 / HYB2-002 / CHR3-008). |
| **AppleScript hardcoded ROOT** | Rebuild required per machine; duplicates launcher ROOT (CHR2-009). |
| **Docs mix “PartyRock Chrome” / legacy profile / OpenClaw CDP** | Operators don’t know which Dock icon is login vs fill vs UI. |

`open_partyrock.sh` itself is **not** unnecessary — it’s the human re-auth path that agent fallback should cite instead of a generic browser tool. What’s unnecessary is **overlapping OpenClaw CLI advice** and **legacy profile mythology**.
